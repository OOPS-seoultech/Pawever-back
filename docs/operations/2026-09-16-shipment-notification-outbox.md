# 준등기 발송 알림 outbox

우체국 접수 결과를 주문에 반영하는 트랜잭션에서 정산 평가와 발송 알림 이벤트를 함께 저장한다. 외부 알리고 호출은 별도 worker가 수행한다. 같은 주문과 송장 조합은 한 이벤트만 생성하므로 우체국 결과를 다시 반영해도 정산이나 알림이 중복되지 않는다.

알리고 발송 API의 `code=0`은 제공자 요청 접수일 뿐 고객 수신 성공이 아니다. 이때 이벤트는 `ACCEPTED`이고, 상세 결과 조회에서 운영 설정의 최종 성공 코드가 확인된 경우에만 `SUCCEEDED`가 된다. 조회 중·결과 없음은 `UNKNOWN`, 명시적 실패는 `FAILED`다. 실패한 이벤트만 관리자 사유와 함께 재시도할 수 있으며 성공·접수·확인 중인 이벤트는 재전송하지 않는다. SMS 대체 발송은 사용하지 않는다.

실제 발송은 기본적으로 꺼져 있다. `ALIGO_ALIMTALK_ENABLED=true`, 발신 프로필 키, 승인 템플릿 코드·제목, 승인 본문의 Base64와 SHA-256, 알리고가 확인해 준 최종 성공 결과 코드가 모두 있어야 worker가 동작한다. 승인 본문 hash가 다르거나 알 수 없는 템플릿 변수가 남으면 전송하지 않는다. 현재 승인 템플릿 원본과 최종 성공 코드를 전달받지 못했으므로 운영 설정은 OFF로 유지한다.

관리자 우체국 결과 화면은 알림 설정 대기, 제공자 접수·수신 확인 중, 수신 성공, 실패를 구분한다. 전화번호·보호자명·반려동물명·주소·렌더링 본문은 암호화해 저장하고 API에는 노출하지 않는다. 최종 성공 결과를 반영하기 전 현재 주문의 수신번호 hash와 송장이 발송 시점 snapshot과 같은지 다시 확인한다.

검증은 알리고 form/응답 파싱 단위 테스트, 상태 전이·수신자 변경 방어 테스트, 송장·정산·outbox 멱등 통합 테스트, 관리자 재시도 E2E로 구성한다. CI의 MariaDB 11 서비스에서 V17부터 최신 V25까지 순차 migration하고 기존 주문·제작·배송 데이터 보존과 신규 테이블 초기 상태를 확인한다.
