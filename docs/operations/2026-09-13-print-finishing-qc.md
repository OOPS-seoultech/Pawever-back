# 출력·후가공·품질 검수

성공 기준: 확정 플레이트를 한 번에 시작하고 주문별 결과를 한 번에 기록한다. 성공 주문은 후가공과 검수를 거쳐 PACKING에 도달하며 실패 주문은 별도 새 시도로 보정한다. 정산 발생 시점은 이후 2차 기획 반영 문서인 [발송·직접 수령 완료 기준 정산](2026-09-16-fulfillment-settlement-pickup.md)으로 대체되었다.

근거: [최종 이관서 §9.4·9.7](2026-09-11-pawever-developer-final-handoff.md), [운영 명세 §8.4·9.5·21.3](../superpowers/specs/2026-09-10-pawever-admin-operations-ux-design.md). 정산 조건은 나중에 작성된 최종 이관서의 ON/유급 대상 조건을 적용한다. 실제 송금, 추가 정산 승인, 포장·발송, 프린터 원격 구동은 이번 범위가 아니다.

재출력은 실패 이슈와 새 attempt를 만든 뒤 PLATE_PREPARATION에서 실패 주문만 다시 구성한다. 성공 주문이 함께 배치된 기존 출력 파일을 그대로 실행하지 않도록 새 플레이트·새 파일 확인 후 PRINT_QUEUE로 인계한다. 기존 완료된 모델과 부위별 색상 지정은 재사용한다. 이는 최종 이관서의 ‘새 출력 시도’를 기존 플레이트 구성 흐름으로 연결하는 구현 결정이다.

후가공은 서포트 제거·표면 확인 및 레진 경화 완료/레진 미사용을 기록한다. 검수는 형상·색상, 표면·마감, 눈·코 등 핵심 부위를 확인한다. 불합격은 사유와 보정 경로(모델 수정, 재출력 구성, 후가공 재작업)를 남기고 새 작업 시도를 생성한다. 이전 기록은 유지한다.

- [x] 후가공/QC 기록, 실패 보정, 선택적 정산 기록 구현.

실제 팀원 계정·재고·주문은 임의로 생성하거나 변경하지 않는다. 정산은 기본 OFF이며 기존 QC 기록의 소급 정산은 하지 않는다. 별도 workspace 배포 기록에 실제 검사 수와 커밋, 운영 검증 결과를 남긴다.

출력 중 담당자 변경은 ASSIGN_WORK 관리자가 포함 주문 전체를 함께 이관한다. 출력 전 주문 취소·프린터 변경 등으로 배치를 사용할 수 없으면 관리자가 사유를 적고 `cancel-queued`로 해제한다. 활성 주문만 새 플레이트 준비 시도로 보내고 기존 파일·배치 기록은 보존한다. 출력 도중 취소·결제·배송 상태가 변경된 주문은 종료 결과에서 SKIPPED로 기록하고 제작 인계에서 제외한다.

API: `POST /api/production/print-batches/{id}/start`, `/observations`, `/finish`, `/cancel-queued`. 시작·종료·대기 해제에는 배치 version과 포함 주문 전체의 version이 필요하다. 중간 기록에는 배치 version, 선택적인 퍼지 무게, 공통 메모와 이상 주문별 메모를 받는다. `POST /api/production/tasks/{id}/post-processing`, `/quality-check`는 현재 담당자의 주문 version과 확인/판정 내용을 받는다. 변경에는 멱등 키가 필요하고 계정·정렬된 주문 잠금으로 경합을 제어한다.

관리자는 `GET/POST /api/admin/production-compensation`에서 활성 유급 담당자 목록과 정산 ON/OFF를 설정하고 `GET /api/admin/production-settlements`에서 항목을 확인한다. 정산 항목은 주문번호와 QC 작업에 고유 제약을 두며 지급 완료를 의미하지 않는다. 파일 권한이 회수되면 후가공·검수 권한도 제거한다.

V21은 기존 배치에 시작/종료 시각을 추가하고 출력 결과·중간 기록·후가공/QC 기록·정산 설정·유급 대상자·정산 항목 테이블을 신설한다. 실제 MariaDB에서 통합 41개와 V20→V21 기존 주문·배치·파일 보존 검사 1개가 통과했다. 재시도, 부분 실패, 취소된 주문 제외, 검수 동시 요청의 중복 정산 방지, 권한 회수, 출력 중 배치 이관, 정산 대상 재저장을 포함한다.
