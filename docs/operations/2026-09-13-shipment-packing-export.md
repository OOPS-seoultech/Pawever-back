# 포장 완료와 우체국 제출 파일

## 범위와 출처

- [최종 이관서 §9.5, §15.1](2026-09-11-pawever-developer-final-handoff.md): 배송 주문 다중 선택, 전체 검증, 무헤더 6열 XLSX, 동일 배치 재다운로드, `COMPLETE + AWAITING_POST_OFFICE_RESULT`.
- [상세 요구서 §5.4, §14.1](../superpowers/specs/2026-09-10-pawever-admin-operations-ux-design.md): `PACK_AND_EXPORT_SHIPMENTS`와 기본 정보·보호자·연락처·주소·배송 조회 권한 의존성, 주문 버전/잠금/재시도/행 스냅샷.
- [개발 보완서](2026-09-12-development-addendum.md): 기존 결제·가격·판매 채널 유지, 실제 우체국 반환 샘플 없이 parser 활성화 금지. 사용자는 2026-09-13 대화에서 샘플을 아직 받지 못했다고 확인했다.
- 직접 수령 장소의 필수 기록과 장소별 목록은 최종 이관서 §9.6 요구사항이다. 미기록 과거 주문의 처리 정책은 아직 답변 대기이며, 이번 변경으로 장소를 채우거나 신규 판매 채널을 확대하지 않는다.

## 구현

관리 메뉴 `/admin/shipments`에서 검수를 통과한 배송 주문을 최대 100건 선택한다. 주문 버전·권한·제작 및 결제 상태·차단 이슈·중복 배치·보호자명·반려동물명·우편번호·전화번호·기본 주소를 서버에서 검증한다. 상세 주소는 실제 값이 없으면 빈 텍스트로 남기며 가짜 주소를 채우지 않는다. 실패 시 주문별 사유를 반환하고 전체 선택의 상태를 유지한다.

파일을 성공적으로 만든 후에만 파일과 행 스냅샷 저장, 포장 작업 완료, 배송 결과 대기 이동, 감사 기록을 한 트랜잭션으로 반영한다. 포장 완료 시 배달 완료일이나 개인정보 파기 기준일을 설정하지 않는다. 같은 요청 식별자는 같은 배치를 반환하며, 다른 요청에서 이미 내보낸 주문을 다시 선택할 수 없다.

첫 시트는 `준등기`, 첫 행부터 데이터, A~F 순서는 보호자명·우편번호·기본 주소·상세 주소·전화번호·반려동물명이다. 모두 텍스트 셀이며 이름은 원문, 우편번호 앞자리 0은 그대로, 전화번호는 숫자만 저장한다. 주문번호나 수식은 파일에 넣지 않는다. XLSX 생성은 [Apache POI 5.5.1](https://poi.apache.org/download.cgi)을 사용한다.

V22는 `shipment_export_batches`, `shipment_export_items`만 추가하고 기존 주문을 자동 변경하지 않는다. 생성 파일의 정확한 바이트와 행별 원문/정규화 값은 기존 AES 변환기로 암호화한다. 행 번호·주문 ID·정규화 지문·생성자·시각을 저장한다. 재다운로드는 현재 권한과 모든 포함 주문의 접근/보관 상태를 다시 확인하고 감사 기록을 남긴다. 취소되거나 보관 기간이 끝난 주문이 있으면 파일 제공을 차단하고 기존 파기 작업에서 파일과 해당 행 스냅샷을 지운다.

기존 송장 등록·수령 완료 API는 새 제작 절차에 들어온 주문의 단계를 우회하지 못하게 한다. 내부 배송 완료 API로 개인정보 보관 기간을 조기에 시작하는 통로도 차단한다. 이전 방식의 미전환 주문에는 기존 통로를 유지한다. 새 결과 가져오기·접수·배달 완료·직접 수령 기능은 이번 배포 완료 항목에 포함하지 않는다.

## 완료 확인

- [x] 미구현 API/기존 우회 동작을 실패 테스트로 재현한 후 구현.
- [x] XLSX 6열 텍스트/앞자리 0/이름 원문/수식 방지, 파일 재다운로드, 전체 취소, 동시 요청, 권한 회수, 파일 생성 실패 및 개인정보 파기 검사.
- [x] 실제 MariaDB 마이그레이션 및 업무 통합 49개 통과. 초기 예약어 충돌을 수정한 새 V22로 전체 재검증했다.
- [x] 전체 서버 401개 통과(기본 환경의 MariaDB 전용 1개 제외), 프런트 타입·빌드·단위 390개, 전체 브라우저 96개(조건 미충족 1개 제외) 및 최종 배송 브라우저 4개 통과.
- [x] 운영 DB 백업과 gzip 검증 완료. CI·운영 배포 결과와 읽기 검증은 배포 결과 기록에서 확인한다.

운영 고객 주문을 테스트용으로 수정하거나, 샘플 없이 반환 파일을 자동 반영하거나, 고객에게 알림을 발송하지 않는다.
