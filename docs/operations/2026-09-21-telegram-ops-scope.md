# Telegram 검수방 연동 범위 결정

결정일: 2026-09-21  
상태: 운영 적용

## 현재 운영 범위

`PAWEVER_ops_bot`은 모델 검수 대기 알림만 검수방으로 보낸다.

- 모델링 산출물 `4면도`, `모델 원본`, `출력 모델`이 모두 등록되고 `MODEL_REVIEW` 작업이 만들어진 뒤에만 발송한다.
- 메시지에는 주문번호와 산출물 종류만 넣는다. 고객 개인정보, 원본 사진, 파일 링크는 넣지 않는다.
- 기존 입금방 알림과 토큰·대상 방을 분리한다.
- Telegram 메시지는 주문 상태나 작업 상태를 변경하지 않는다.

## 의도적으로 만들지 않은 범위

2차 요구사항에는 "직원 계정 연결, 버튼 콜백 수신, 입금방(대표)·검수방(실무자) 분리"라는 Telegram 양방향 요구가 있다. 현재는 그중 방 분리와 검수방 알림만 적용했다.

다음 기능은 미구현이 아니라 보류다.

- Telegram 직원 계정과 PAWEVER 직원 계정 연결
- Telegram 인라인 버튼, callback webhook 또는 long polling 수신
- Telegram에서 작업 가져오기, 검수 승인·수정 요청, 상태 변경 실행
- Telegram 입력으로 파일·사진·주문 상세를 열람하거나 수정하는 기능

## 보류 이유

운영 결정은 "알림만 보내면 돼"이다. 현재 목적은 모델 검수 대기 사실을 실무자에게 전달하는 것이며, 검수·수정·상태 변경은 이미 권한, 파일 확인, 사유, 버전 충돌 처리를 갖춘 관리자 웹에서 수행한다.

그룹 메시지의 버튼으로 주문 상태를 바꾸려면, 허용 직원과 Telegram 사용자 ID의 연결·해제·퇴사 처리, 버튼별 권한, 동시 클릭·재전송, 오류 복구, 감사 기준을 먼저 확정해야 한다. 이 결정 없이 양방향 제어를 추가하면 업무 속도보다 잘못된 상태 변경과 권한 우회 위험이 커진다.

따라서 현재 단방향 알림은 축소 구현이 아니라, 운영상 필요한 범위로 의도적으로 제한한 구현이다.

## 재개 조건

양방향 기능은 다음을 운영 책임자가 확정한 뒤 별도 작업으로 연다.

1. Telegram에서 허용할 행동 목록과, 각 행동을 실행할 역할
2. 직원 계정 연결·해제·비활성화 절차
3. 버튼 실행 실패·동시 실행·재시도 시의 사용자 경험과 감사 기준
4. webhook 공개 URL·비밀값 관리와 운영 담당자

첫 범위는 `검수 화면 열기` 링크 또는 `내 작업으로 가져오기`처럼 되돌릴 수 있는 행동으로 제한한다. 검수 승인·수정 요청·파일 확인·주문 상태 변경은 관리자 웹에서 계속 처리한다.
