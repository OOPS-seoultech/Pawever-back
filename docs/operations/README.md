# 관리자 운영 시스템 개발 문서

입금 확인부터 모델링·검수 인계까지의 1차 기능은 2026-09-12 운영 배포했다. [첫 구현 결과](2026-09-12-first-flow-implementation.md)는 배포 전 검증 기록이며, 이후 DB 백업·V17 적용·운영 API·비공개 저장소 확인을 완료했다. 현재 추가한 [모델 검수 승인·수정 요청](2026-09-12-model-review-decisions.md)의 완료 범위와 검사 결과를 함께 읽는다.

첫 범위와 작업별 완료 조건은 [1차 개발 계획 — 입금 확인부터 검수 인계까지](../superpowers/plans/2026-09-12-first-production-handoff.md)에 정리했다. 실제 직원 계정·기본 담당자 지정, 실무 모델 파일로 한 건 처리, 과거 주문별 전환은 운영 확인 항목으로 남아 있다. 계정이나 과거 제작 중 주문에 담당자를 자동 지정하지 않았다.

## 읽는 순서

추가 구현: [출력·후가공·검수](2026-09-13-print-finishing-qc.md), [포장 완료·우체국 제출 파일](2026-09-13-shipment-packing-export.md), [발송·직접 수령 완료 기준 정산](2026-09-16-fulfillment-settlement-pickup.md). 정산 발생 기준은 최신 2차 기획에 따라 마지막 문서를 우선한다.

[개발 보완서](2026-09-12-development-addendum.md)를 먼저 읽고 [원본 운영 명세의 개발용 사본](../superpowers/specs/2026-09-10-pawever-admin-operations-ux-design.md), [최종 이관서](2026-09-11-pawever-developer-final-handoff.md), [작업별 구현 계획](../superpowers/plans/2026-09-11-pawever-admin-notion-integration.md), [Notion 변경 지시서](2026-09-11-notion-gpt-change-request.md)를 따른다. 정책 충돌 Q1~Q3는 보완서에 미답변으로 남겼다.

## 이번에 정리한 내용

현재 판매의 가격·키링·입금 기한·정원·재신청 규칙을 보존 대상으로 추가했다. 새 역할과 제작 API의 인증, 중복 요청 방지, 데이터 이전 검증을 개발 작업에 포함했다. 송장 NULL, Notion 보기 API, 잘못된 설정 파일 경로를 정정했다. 권한 이름은 원본 명세 기준으로 맞추고 추가 키는 보완서에 구분했다.

다운로드 원문은 보존했다. 이 저장소의 사본을 공동 개발 기준으로 사용하며 프론트 저장소에는 중복 사본을 두지 않는다. 사본의 기존 표는 원문 보존용일 수 있으므로 해당 절 앞의 충돌 안내와 보완서를 함께 읽는다.

## 운영자에게 확인할 내용

수령 주문의 장소와 앞으로 허용할 채널, 실제 제작 단계를 모르는 주문의 처리, 삭제 주문 복구를 허용할 관리자 범위다. [보완서 Q1~Q3](2026-09-12-development-addendum.md)에 질문과 영향 범위를 적었다. 이 질문과 무관한 개발 작업은 계속할 수 있다.
