# 발송·직접 수령 완료 기준 정산

최신 2차 기획의 완료 기준에 맞춰 제작비 정산 발생 시점을 품질 검수 통과에서 실제 이행 시점으로 옮겼다. 배송 주문은 우체국 접수 결과를 확정할 때, 직접 수령 주문은 OWNER가 포장을 완료할 때만 주문당 한 번 정산한다. 알림 성공이나 고객의 실제 수령 완료는 정산 조건이 아니다.

## 운영 흐름

- 품질 검수 통과: 포장 작업을 만들고 정산은 `PENDING_FULFILLMENT`로 남긴다.
- 배송: 포장·XLSX 내보내기만으로는 정산하지 않는다. 우체국 결과를 주문에 반영할 때 정산 대상 여부를 평가한다.
- 직접 수령: `포장·준등기` 화면에서 포장을 완료하면 `COMPLETE + READY_FOR_PICKUP`으로 이동하고 정산을 평가한다. 이후 전체 주문 화면의 `수령 완료`는 실제 고객 인도만 기록하며 정산을 추가하지 않는다.

정산 기능 OFF, 비지급 담당자, 검수 기록 누락은 각각 `DISABLED`, `UNPAID_WORKER`, `REVIEW_REQUIRED`로 남는다. 기존 주문당 고유 제약과 주문 잠금을 유지하므로 재시도·동시 요청으로 중복 정산되지 않는다. 기존 QC 기준으로 이미 생성된 원장은 삭제하거나 소급 변경하지 않는다.

## API와 배포

- `GET /api/admin/shipments/pickup-candidates`: 직접 수령 포장 대기 목록.
- `POST /api/admin/shipments/pickup-completions`: 선택 주문의 포장 작업 완료와 정산 평가. `Idempotency-Key`가 필수다.
- 기존 `POST /api/admin/orders/{orderNumber}/pickup-complete`: 새 제작 흐름에서는 `READY_FOR_PICKUP` 이후 OWNER만 실행할 수 있다.

스키마 변경은 없다. 운영 배포 후 배송 1건의 우체국 접수와 직접 수령 1건의 포장 완료를 확인하고, 각 주문의 정산 원장이 한 건만 생성되는지 확인한다. 실제 주문을 시험하기 어렵다면 정산 기능은 그대로 OFF로 두고 화면·권한·상태 전이까지만 확인한다.
