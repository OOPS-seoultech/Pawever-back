# 굿즈 자료 보관 정책 대조와 결정 기록

작성일: 2026-09-19  
상태: **결정 대기 — 이 문서는 동작을 변경하지 않는다.**

## 현재 운영 기준

- 공개 개인정보처리방침은 제품의 배송 정보·굿즈 사진을 **배송 완료 후 90일** 보관한다고 고지한다. `Pawever-landing/client/src/pages/PrivacyPolicy.tsx`의 제품 행과 제5조를 기준으로 한다.
- 서버 기본값도 `survey.goods.personal-data-retention-days: 90`이다. 배송 완료 시 `deleteAfter`를 그 시각 + 90일로 기록한다. `src/main/resources/application.yaml`, `GoodsSurveyFulfillment#markDeliveryCompleted` 참조.
- 매일 실행되는 보관 작업은 `deleteAfter`가 지난 주문의 비공개 고객 사진을 저장소에서 삭제하고, 상세주소를 제거한다. 확정 제작 자료도 같은 `deleteAfter` 기준으로 삭제한다. 주문·결제·공급 계약 기록은 별도 5년 보존 경로다.
- 현재 AS grant는 보관 시계를 멈추지 않는다. 이미 `deleteAfter`가 지난 주문에는 자료 목록이나 새 링크를 발급하지 않는다. `AsCaseService#retained` 참조.

따라서 이 문서 작성 시점의 실제·공개 기준은 **90일**이다.

## 충돌하는 문구

- 굿즈 신청 화면은 “굿즈 발송일로부터 3주 뒤 모두 삭제”라고 고지한다. `Pawever-landing/client/src/pages/goodsSurveyContent.ts` 참조.
- 저장소의 개인정보처리방침 개정문안도 굿즈 신청 정보·사진을 발송일로부터 **3주**라고 적는다. `Pawever-landing/docs/개인정보처리방침_개정문안.md` 참조.
- 2차 기획 PRD R15는 고객 사진·출력 도면/4면도·3D 렌더·원본 모델/3MF를 **3개월** 보관하는 안을 제시한다. 단, 기존 3주·90일 고지와의 충돌을 배포 전 통일하라고 명시한다.

`3개월`은 달력상 90일과 같지 않을 수 있다. 결정 문구는 반드시 “90일” 또는 “배송 완료일로부터 3개월” 중 하나로 고정해야 한다.

## OWNER 결정이 필요한 항목

1. 제작용 고객 사진·상세주소·비공개 제작 자료의 기간을 `3주`, `90일`, `3개월` 중 하나로 확정한다.
2. 기산일을 배송 완료 시각으로 유지할지, 발송/직접 인도 시각 등 다른 사건으로 바꿀지 확정한다.
3. 새 기준이 기존 주문에도 적용되는지, 고지·동의 버전별로 구분할지 결정한다.
4. 계약·결제·공급 기록의 5년 보존과 분리되는 필드를 확정한다. 사진·상세주소·파일은 계약 기록으로 취급하지 않는다.

## 결정 후 구현 순서

1. 고객 화면의 신청 동의 문구, 공개 개인정보처리방침, 개정문안을 같은 기간·기산일로 수정한다.
2. `personal-data-retention-days`와 테스트 기대값을 같은 정책으로 바꾼다. 달력상 3개월을 선택하면 단순 일수 설정 대신 월 단위 계산 규칙을 별도 구현한다.
3. 기존 주문의 `deleteAfter` 재계산 대상·범위·dry-run 결과를 검토한다. 즉시 삭제 migration은 만들지 않는다.
4. 사진, 제작 자료, 상세주소, 계약 기록, AS grant 각각에 대해 경계 시각 전/정각/후 테스트와 복구 절차를 추가한다.
5. 사전 백업, 복제 DB dry-run, OWNER 승인 뒤에만 실제 데이터 변경을 실행한다.

## 지금 하지 않는 일

- scheduler를 중지하거나 AS grant로 파일 보존을 무기한 연장하지 않는다.
- 기존 주문·사진·제작 자료를 일괄 삭제하거나 `deleteAfter`를 즉시 재작성하지 않는다.
- 2차 기획의 3개월 문구만 믿고 공개 고지와 실제 90일 동작을 불일치 상태로 배포하지 않는다.
