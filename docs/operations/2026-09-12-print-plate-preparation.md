# 플레이트 구성과 출력 대기 인계

성공 기준은 색상 지정이 완료된 담당 주문 1–50개를 플레이트로 묶고, 실제 프린터 이름·필라멘트 슬롯·출력 담당자·출력 파일을 확인한 뒤 모든 포함 주문을 PRINT_QUEUE로 함께 넘기는 것이다. 실제 프린터 구동·출력 결과·후가공·최종 검수는 다음 개발 범위다.

## 근거와 이번 범위

[최종 이관서 §9.3](2026-09-11-pawever-developer-final-handoff.md)은 실제 필라멘트 조합의 주문을 PrintBatch로 묶고 3MF/G-code·프린터·슬롯을 저장한 뒤 확정 시 전체 주문을 PRINT_QUEUE로 이동하도록 요구한다. [운영 명세 §5.4·8.3·9.5](../superpowers/specs/2026-09-10-pawever-admin-operations-ux-design.md)는 MANAGE_PRINT_BATCH의 데이터 권한 의존성, 사람이 최종 묶음을 결정하는 것, 출력 기본 담당자와 제작 담당자의 파일 조회를 규정한다.

프린터 기종·수량과 고정 슬롯 체계는 원문에 없으므로 실제 프린터 이름(80자)과 슬롯 이름(30자)을 입력한다. 자동 후보 추천과 물리 프린터 연결은 추가하지 않는다. 1–50개 주문과 최대 64개 실제 스풀은 이번 화면/API의 입력 한도다. 하나의 실제 스풀을 여러 슬롯에 중복 지정하거나 슬롯 이름을 중복 사용할 수 없다. 사용하는 스풀 전체와 슬롯의 스풀 집합이 일치해야 확정한다. 재질·마감과 색상은 주문의 완료된 매핑 기록을 표시하며 최종 배치의 적합성은 담당자가 슬라이서에서 확인한다.

## 동작과 보호 규칙

DESIGN_QC는 본인에게 배정된 PLATE_PREPARATION 주문을 선택한다. 임시 플레이트에 포함된 주문은 다른 플레이트에 다시 넣거나 주문 단위로 재배정할 수 없다. 임시 구성에서 주문 추가·제외·프린터·슬롯을 바꾸면 구성 회차가 증가하고 기존 파일의 확정 자격을 해제한다. 출력 담당자만 바꿀 때는 같은 파일을 유지한다. 임시 구성을 취소하면 주문의 단계는 유지하며 예약을 해제한다. 관리자는 담당자가 비활성화되거나 권한을 잃은 임시 플레이트도 취소할 수 있다.

확정에는 모든 포함 주문의 최신 version, 현재 구성의 확인된 3MF 또는 G-code 파일 1개, 사용 가능한 실제 스풀과 전체 슬롯, 활성 PRINT_FINISHING 담당자, 파일의 주문 배치·슬롯 일치 확인이 필요하다. 하나라도 충족하지 않으면 어떤 주문도 이동하지 않는다. 계정 잠금·정렬된 주문 잠금·플레이트/주문 version·멱등 키·작업별 고유 예약을 사용해 경합과 재시도를 처리한다. 확정 시 각 주문의 플레이트 작업을 완료하고 PRINT_QUEUE 작업을 생성한다. 운영 화면의 상태 이름은 ‘출력 대기’다.

기본 출력 담당자는 기존 기본 배정 설정에 선택 항목으로 추가하며 실제 계정을 자동 설정하지 않는다. 예전 클라이언트가 printing을 생략해도 기존 설정을 지우지 않는다. 확정한 배치의 담당자는 ASSIGN_WORK 관리자가 포함 주문 전체에 대해 변경한다. 일반 주문 재배정으로 배치 담당자가 어긋나지 않게 한다.

OWNER/ADMIN과 DESIGN_QC/PRINT_FINISHING에 MANAGE_PRINT_BATCH를 부여하되 VIEW_ORDER_BASIC·VIEW_PRODUCTION_FILES·VIEW_FILAMENT 중 하나를 잃으면 사용할 수 없다. 배치 조회는 모든 포함 주문의 열람 권한이 있어야 한다. 출력 담당자는 실제 작업을 인계받은 뒤 조회한다. 파일 링크는 추가로 DOWNLOAD_PRODUCTION_FILES가 필요하다. 취소 주문이나 파일 보관 기간이 끝난 주문이 포함되면 파일을 내려주지 않는다.

파일은 기존 비공개 S3의 production/print-batches 아래에 저장한다. 100MB 이하의 .3mf 또는 .gcode만 받으며 업로드 후 크기·내용 유형과 파일 선두 바이트를 확인한다. 3MF는 ZIP 시그니처, G-code는 NUL 바이트 없는 형식인지 확인하는 수준이며 슬라이서 구조·프린터 명령의 의미를 검증하거나 실행하지 않는다. 가장 최근에 확인한 파일 하나를 현재 파일로 지정한다. 서명 URL은 멱등 응답 저장소에 저장하지 않는다.

## API와 화면

- GET /api/production/print-batches, /candidates, /staff, /{id}: 배치·담당 후보·출력 담당자 조회.
- POST /api/production/print-batches, /{id}: 주문 version 목록과 printerName·printingAssigneeId·slots를 임시 저장. 수정은 배치 version도 필요.
- POST /{id}/confirm: 배치 version, 모든 주문 version, layoutChecked=true로 확정. /cancel은 임시 취소, /assign은 확정된 출력 대기 배치의 담당자 변경.
- POST /{id}/artifacts/upload-requests, /{id}/artifacts/{fileId}/confirm, /download-link: 파일 업로드 요청·확인·단기 열람 링크. 모든 변경에는 Idempotency-Key가 필요하다.

/admin/print-batches에서 구성·파일 등록·확정·취소·열람을 수행한다. /admin/my-work에서 연결된 플레이트를 직접 열 수 있고 /admin/accounts에서 출력·후가공 역할과 기본 담당자를 지정한다.
