# 굿즈 2차 판매 — 열기 전 확인 목록

`goods_survey_campaigns.goods_open`을 `TRUE`로 바꾸는 순간 굿즈 신청 화면이
다시 열린다. 그 화면은 **1차 무료 제작을 전제로 만들어져 있다.** 스위치를
켜기 전에 아래를 먼저 처리해야 한다.

기준일: 2026-08-10

---

## 보류한 결정

### 2차 안내 연락 수단 — 이메일 유지, 휴대전화 전환 보류

11차 회의록은 설문에서 **이름과 휴대전화를 필수로** 받고 SMS·카카오톡 광고
수신 동의를 분리하도록 정했다. 지금은 **이메일 한 칸(선택)** 구조를 유지하고,
휴대전화 전환은 뒤로 미룬다.

미룬 이유는 개발량이 아니라 **선행 조건**이다. 조사한 내용:

| | 이메일 (지금) | 휴대전화 (보류) |
|---|---|---|
| 수집 구현 | 완료 | 더 쉬움 — `normalizePhone()`·`PHONE_PATTERN`·`phone_hash`를 그대로 쓴다 |
| 발송 구현 | HTTP API 하나 | 대행사 SDK + 발신번호 관리 + 수신거부 + 발송 이력 |
| 발송 단가 | 사실상 0 | LMS 25~35원, 친구톡 13~20원 |
| 고정비 | 없음 | 080 수신거부 번호 월 1~2만원대 |
| **선행 조건** | **없음** | **사업자등록 → 발신번호 사전등록(통신사 심사)** |
| 도달률 | 오픈율 20~30% | 사실상 전부 도달 |

비용은 문제가 아니다. 500명 발송이 1.5만원 수준이고 제품 하나 값이면 나온다.
막는 것은 **사업자등록증 없이는 발신번호를 등록할 수 없다**는 점이다.

**재개 조건:** 사업자등록 완료 → 발신번호 등록 → 080 번호 확보.
그 시점에 회의록 §7·§8(이름·휴대전화 필수, 동의 4종 분리)을 한 번에 적용한다.
지금 이름만 먼저 받아 두지 않는 이유도 같다. 수집 항목은 발송 수단과 함께
설계해야 고지 문구가 어긋나지 않는다.

**카카오톡을 쓸 때 반드시 알아야 할 것** — 회의록 §7은 광고성 카카오톡 수신
동의를 "동의 **또는** 채널 추가"로 적었는데, 이 둘은 대체재가 아니다.
**친구톡은 채널을 추가한 친구에게만 발송된다.** 동의 체크박스만 받고 채널
추가를 유도하지 않으면 한 통도 보낼 수 없다. 체크박스 옆에 채널 추가 동선을
반드시 붙여야 한다.

## 굿즈를 다시 열기 전에 반드시

### 1. "제작비는 0원" 필수 동의 문구 — 유료 상품에 그대로 뜬다

`Pawever-landing` 제작 정보 화면에 이 동의가 남아 있다.

> 제작비는 0원이며 배송비 3,000원이 별도임을 확인했습니다. (필수)

지금은 굿즈가 닫혀 도달할 수 없지만, 스위치를 켜는 순간 **유료 상품 결제
직전에 "제작비 0원" 확인 체크박스가 뜬다.** 금액이 확정돼야 고칠 수 있어
그대로 두었다.

### 2. 청약철회·환불 조항이 없다

`TermsOfService.tsx`에는 **"무료 서비스 손해배상 면책" 조항만** 있다.
유료 판매에는 전자상거래법상 청약철회 기간·방법·환불 조건 표시가 필요하다.

주문제작품은 청약철회를 제한할 수 있지만(전자상거래법 제17조 제2항 제5호),
**사전에 별도로 고지하고 동의를 받아야** 그 제한이 유효하다. "주문제작이라
환불 불가"만 적어 두면 무효다.

### 3. 판매자 정보 표시

상호·대표자·사업자등록번호·**통신판매업신고번호**·주소·연락처.
통신판매업 신고는 사업자등록이 선행이다.

### 4. 결제 수단

PG 또는 간편결제 계약. 심사에 1~2주.

> **1~4는 모두 사업자등록이 선행이다.** 코드보다 이쪽 리드타임이 길다.

## 운영 부채

### 개인정보 자동 파기 장치가 없다

`delete_after`는 기록만 하고 실제로 지우는 스케줄러가 없다
(`@EnableScheduling` 자체가 없다). 대상:

- `goods_survey_fulfillments` — "굿즈 발송일로부터 3주 뒤 삭제"로 안내
- `goods_survey_notice_subscriptions` — "수집일로부터 1년"으로 안내

**고지한 기간이 지나면 사람이 직접 지워야 한다.**

### 수신거부는 사람이 처리한다

수신거부 페이지와 토큰을 만들지 않기로 했다. 문의를 받으면
`goods_survey_notice_subscriptions.unsubscribed_at`을 채우고, 발송 대상을
뽑을 때 **이 칸이 비어 있는 행만** 골라야 한다. 둘 중 하나라도 빠지면 해지를
요청한 사람에게 다시 발송된다.

### 1차 신청자 100명에게는 광고성 메시지를 보낼 수 없다

신청 화면의 이용 목적이 "굿즈 제작·발송, 문의 대응"으로 한정돼 있어
**광고 수신 동의를 받은 적이 없다.** 보유 기간도 발송 3주 뒤까지다.
2차 안내 대상은 지금부터 새로 동의를 받는 사람뿐이다.
(`scripts/survey-export/README.md`에도 같은 내용이 있다)

## 스위치를 켤 때

```sql
UPDATE goods_survey_campaigns
   SET goods_open = TRUE, updated_at = CURRENT_TIMESTAMP(6)
 WHERE id = 'goods-2026-07';
```

정원도 함께 본다. `capacity - historical_allocated - SUBMITTED수`가 0보다
커야 실제로 열린다. 1차 정원이 100/100이므로 **`capacity`를 2차 수량만큼
올려야 한다.**

수량은 임의로 정하지 않는다(회의록 §2).
`2주간 안정적으로 제작 가능한 수량 - 재제작 여유분 10%`로 확정한다.
